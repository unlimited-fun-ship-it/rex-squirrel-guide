Player Choice Events — Squirrel Scripting in REX

This tutorial shows you how to create scripted events that present the player with a binary choice, using the REX Community Patch’s Squirrel API. It mirrors the classic message_prompt / ScriptPromptCallback pattern from Rome Remastered, but implemented in Squirrel.

Introduction

In Rome Remastered you can create events that force the player to make a choice before continuing. In REX Squirrel, the same idea is achieved with the raiseEvent method on the campaign object and the EventCounter event.

The flow is:

  1. Trigger – something happens (e.g., a faction’s turn starts) and your conditions are met.
  2. Raise the choice – you call ::campaign.raiseEvent(...) with isChoice = true. This shows a message with Accept / Decline buttons. The engine automatically bumps two event counters: <name>_accepted and <name>_declined.
  3. Handle the reply – you listen for the EventCounter event. When the player clicks a button, the corresponding counter changes, and your handler runs.
  4. Reset – you reset the counters so the event can be triggered again in the future (or mark it as done).

This replaces the old declare_counter / message_prompt / ScriptPromptCallback trio.

Step 1 — The Trigger

We start by listening for a suitable event. For a turn‑based choice, FactionTurnStart is a good candidate.

::events.on("FactionTurnStart", function(payload) {
    // The payload should contain the faction whose turn it is.
    // Check the API docs for the exact field name – it may be `faction`.
    local faction = payload.faction;
    if (faction == null) return;

    // We only want this for the human Julii player.
    if (faction.name != "romans_julii") return;
    if (::game.localFactionId() != faction.id) return;

    // Conditions: event not already done, and a 1% random chance.
    if (::game.eventCounter("julii_bribe_senators_done") == 1) return;
    if (rand() % 100 > 0) return;   // 1% chance

    // All conditions met – raise the choice event.
    ::campaign.raiseEvent(
        "senate_01",                       // picture name and counter base
        ::game.text("JULII_BRIBE_TITLE"),  // title text (from expanded_bi.txt)
        ::game.text("JULII_BRIBE_BODY"),   // body text
        true,                              // isChoice = true
        -1, -1,                            // no map position
        [faction.id]                       // only show to this faction
    );
});
Notes
  • ::campaign is the global Campaign object. (There is no ::game.campaign.)
  • ::game.text("KEY") looks up a localised string. You can also pass literal strings if you prefer.
  • raiseEvent returns true if the message was raised.
  • The name you pass ("senate_01") becomes the base for the automatic counters: senate_01_accepted and senate_01_declined.
  • We use a separate counter julii_bribe_senators_done to ensure the event only fires once. Event counters are saved with the campaign, which is safer than a plain variable.

Step 2 — Handling the Reply

When the player clicks Accept or Decline, the engine changes the corresponding event counter. We listen for the EventCounter event to react.

::events.on("EventCounter", function(payload) {
    // The payload contains the counter name and its new value.
    local counterName = payload.name;
    local value = payload.value;

    if (counterName == "senate_01_accepted" && value == 1) {
        // Player chose Yes.
        local playerFaction = ::campaign.factionById(::game.localFactionId());
        if (playerFaction != null) {
            playerFaction.money -= 20000;

            // inc_counter equivalents:
            local support = ::game.eventCounter("romans_julii_support");
            ::game.setEventCounter("romans_julii_support", support + 200);

            local brutii = ::game.eventCounter("romans_brutii_support");
            ::game.setEventCounter("romans_brutii_support", brutii - 100);

            local scipii = ::game.eventCounter("romans_scipii_support");
            ::game.setEventCounter("romans_scipii_support", scipii - 100);
        }

        // Reset the accepted counter and mark the event as done.
        ::game.setEventCounter("senate_01_accepted", 0);
        ::game.setEventCounter("julii_bribe_senators_done", 1);
    }
    else if (counterName == "senate_01_declined" && value == 1) {
        // Player chose No.
        ::game.setEventCounter("senate_01_declined", 0);
        ::game.setEventCounter("julii_bribe_senators_done", 1);
    }
});
Notes
  • The EventCounter event fires for any counter change, including the ones you set yourself. That’s why we check both the name and the value (== 1). When we reset the counter to 0, the event fires again, but the condition fails, so no infinite loop.
  • If the exact payload field names are different, log the payload to see what’s inside: 
    ::events.on("EventCounter", function(payload) {
    ::game.log("EventCounter payload: " + payload);
});
  • The raiseEvent counters are named <name>_accepted and <name>_declined. Make sure the name you pass to raiseEvent matches the counters you check.

Full Example Script

Putting it all together in one file (e.g., player_choice_example.nut inside your mod’s script folder):

// Player Choice Event: Julii Bribe Senators

// 1. Trigger – on Julii turn start, under conditions, raise the choice.
::events.on("FactionTurnStart", function(payload) {
    local faction = payload.faction;
    if (faction == null) return;
    if (faction.name != "romans_julii") return;
    if (::game.localFactionId() != faction.id) return;

    if (::game.eventCounter("julii_bribe_senators_done") == 1) return;
    if (rand() % 100 > 0) return;   // 1% chance

    ::campaign.raiseEvent(
        "senate_01",
        ::game.text("JULII_BRIBE_TITLE"),
        ::game.text("JULII_BRIBE_BODY"),
        true,
        -1, -1,
        [faction.id]
    );
});

// 2. Handle the reply.
::events.on("EventCounter", function(payload) {
    local counterName = payload.name;

    if (counterName == "senate_01_accepted" && value == 1) {

    }
});

Tips and Best Practices

  • Check the API docs – The exact payload field names for events like FactionTurnStart and EventCounter are listed in api.d.nut. If unsure, log the payload to see its contents.
  • Use event counters for state – They are saved with the campaign, so they survive save/load. Perfect for “done” flags.
  • Avoid infinite loops – Always check the counter value (== 1) before acting, and reset it to 0 afterwards.
  • Localisation – Use ::game.text("KEY") to pull strings from expanded_bi.txt (or expanded.txt). This keeps your mod translatable.
  • One event per choice – Give each choice event a unique name so its automatic counters don’t clash with others.
  • Test with high probability – While developing, change rand() % 100 > 0 to rand() % 100 > 99 or just remove the random check so the event fires every turn.

Congratulations!

You have now created a player choice event using REX Squirrel. The player will be presented with a yes/no prompt, and your script reacts to their decision. This is the Squirrel equivalent of the old message_prompt / ScriptPromptCallback system, but with all the power and flexibility of a real scripting language.

Happy scripting!
