Emergent Factions — Squirrel Scripting in REX

An emergent faction is a faction that does not exist on the map at the start of the campaign but can appear later, usually in response to a revolt or a specific historical condition. In vanilla Rome: Total War the Roman Empire emerging from the collapse of the four Roman houses is the classic example; Total Conquest and other mods use the same machinery for breakaway states, rebel kingdoms, and scripted “what if” factions.

This page explains how emergent factions are set up, how their spawn scripts work, and how a Squirrel script can influence whether and when they appear.

Setup — descr_sm_factions.txt

The faction must first be declared with an emergence block in descr_sm_factions.txt, placed before the logos section. This block tells the engine what units the emergent faction gets when it appears inside a settlement, and how strong it should be.

"emergence":
{
    ;; Units to use if we emerge inside a settlement.
    "settlement units":
    [
        "roman praetorian cohort i",
        "roman praetorian cohort i",
        "roman praetorian cohort i",
        "roman praetorian cohort i",
        "roman praetorian cohort i",
        "roman praetorian cohort i",
        "roman praetorian cohort i",
        "roman praetorian cohort i",
    ],
    "strength": 1.5,
},
  • "settlement units" — the list of units the faction receives when it takes over a settlement. The engine fills the settlement’s garrison with these. The list can be as long or short as you like.
  • "strength" — a multiplier applied to the faction’s starting strength. The value here is authoritative for emergent factions; they do not use the normal descr_strat strength.

Setup — descr_strat.txt

In descr_strat.txt, the faction needs a spawn_script line. This tells the engine two things: which script to run, and when to run it.

spawn_script roman_empire, revolt, spawn_scripts/roman_empire.txt
  • First argument — the faction’s internal name (roman_empire). Must match the name used in descr_sm_factions.txt.
  • Second argument — either revolt or end_of_turn:
    • revolt — the script runs whenever a settlement revolts. The engine exports the revolting settlement’s details to the script.
    • end_of_turn — the script runs at the end of every turn, regardless of revolts.
  • Third argument — the path to the spawn script, relative to the campaign folder.

How the spawn script works

The spawn script is written in the old RR script syntax (script … end_script), not Squirrel. It must return either true or false:

  • return true — the faction emerges now.
  • return false — the faction does not emerge this time.

When the spawn fires, the engine places the faction’s army at the settlement that triggered it (for revolt) or at a location the script arranges (for end_of_turn), using the units from the emergence block.

Example — the Roman Empire

The classic scenario: the Roman Empire emerges from Rome when one of the Roman houses collapses, provided at least two of the others are already gone.

script
    if not FactionIsAlive roman_empire
        && SettlementName Rome

        if SettlementRevoltingFrom romans_julii
            && not FactionIsAlive romans_senate
            && not FactionIsAlive romans_scipii
            && not FactionIsAlive romans_brutii
            return true
        end_if
        if SettlementRevoltingFrom romans_scipii
            && not FactionIsAlive romans_senate
            && not FactionIsAlive romans_julii
            && not FactionIsAlive romans_brutii
            return true
        end_if
        if SettlementRevoltingFrom romans_brutii
            && not FactionIsAlive romans_senate
            && not FactionIsAlive romans_julii
            && not FactionIsAlive romans_scipii
            return true
        end_if
    end_if
    ;; else don't spawn
    return false
end_script

Reading it in plain English:

  1. If the Roman Empire is not already alive, and the settlement that revolted is Rome, then:
  2. Check which Roman house the settlement is revolting from.
  3. If that house’s revolt happens while the other two are already dead (and the Senate is gone), return true.
  4. Otherwise, return false.

Bridging from Squirrel

Just like major event scripts, spawn scripts cannot call into Squirrel directly. They are read and executed by the engine, one turn (or one revolt) at a time. And just like major event scripts, they can be influenced through the shared engine state:

  1. Event counters — Squirrel writes them with ::game.setEventCounter; the spawn script reads them with I_CompareCounter.
  2. Hidden resources — Squirrel writes them with Region.setHiddenResource; the spawn script reads them with HasResource.
  3. Live game state — anything the spawn script can already see (faction alive/dead, settlement ownership, resources, buildings, turn number) can be steered by Squirrel through the game API.

Example — emerge once a Squirrel flag is set

Squirrel side:

// Make sure the counter exists before the spawn script looks at it.
::events.on("campaignMapLoaded", function() {
    if (::game.eventCounter("empire_ready") == null) {
        ::game.setEventCounter("empire_ready", 0);
    }
});

// Some game event that arms the emergence.
::events.on("GeneralCaptureSettlement", function(payload) {
    local s = payload.settlement;
    if (s == null) return;
    if (s.name != "Rome") return;

    // The trigger condition has been met.
    ::game.setEventCounter("empire_ready", 1);
    ::game.log("Emergent faction is now armed to appear.");
});

Spawn script (in spawn_scripts/roman_empire.txt):

script
    if not FactionIsAlive roman_empire
        && I_CompareCounter empire_ready = 1
        && SettlementName Rome

        ;; Only emerge from a revolt against a Roman house.
        if SettlementRevoltingFrom romans_julii
            return true
        end_if
        if SettlementRevoltingFrom romans_scipii
            return true
        end_if
        if SettlementRevoltingFrom romans_brutii
            return true
        end_if
    end_if
    return false
end_script
Why this works. ::game.setEventCounter writes to the same counter table that I_CompareCounter reads, and it is saved with the campaign — so the flag persists across save/load. This is the recommended bridge for emergent factions.

Example — end_of_turn emergence with a hidden‑resource flag

Squirrel side:

::events.on("GeneralCaptureSettlement", function(payload) {
    local s = payload.settlement;
    if (s == null || s.name != "Rome") return;

    s.region.setHiddenResource("empire_ready", true);
});

// Hidden resources are not saved — re‑apply on load.
::events.on("campaignMapLoaded", function() {
    local rome = ::stratMap.findSettlement("Rome");
    if (rome == null) return;

    local julii  = ::campaign.factionByName("romans_julii");
    local brutii = ::campaign.factionByName("romans_brutii");
    local scipii = ::campaign.factionByName("romans_scipii");

    // Example condition: two of the three houses are gone.
    local dead = 0;
    if (julii == null)  dead += 1;
    if (brutii == null) dead += 1;
    if (scipii == null) dead += 1;

    if (dead >= 2) {
        rome.region.setHiddenResource("empire_ready", true);
    }
});

Spawn script:

script
    if not FactionIsAlive roman_empire
        for_each settlement in world
            if HasResource empire_ready
                return true
            end_if
        end_for
    end_if
    return false
end_script

Direct emergence from Squirrel

In some REX builds you may be able to emerge a faction directly from Squirrel, bypassing the spawn script entirely. The Faction class exposes a writable status property:

  • 0 — alive.
  • 1 — death pending.
  • 2 — dead.
  • 3 — dead until resurrected.
  • 4 — dead until emerged (Medieval II only).

If your build exposes the emergent status, you can transition a dead faction back into play:

::events.on("GeneralCaptureSettlement", function(payload) {
    local s = payload.settlement;
    if (s == null || s.name != "Rome") return;

    local empire = ::campaign.factionByName("roman_empire");
    if (empire == null) return;
    if (empire.status != 4) return;   // only if currently "dead until emerged"

    // Hand the settlement to the emergent faction.
    s.owner = empire;

    // Spawn a garrison for it, using the units the emergence block
    // in descr_sm_factions.txt declares.
    local army = s.createGarrisonArmy();
    if (army != null) {
        army.createUnit("roman praetorian cohort i", 0, 0, 0, -1);
        army.createUnit("roman praetorian cohort i", 0, 0, 0, -1);
        army.createUnit("roman praetorian cohort i", 0, 0, 0, -1);
    }
});
This is not a full replacement for the spawn script. Emergence involves more than a status flag and a garrison — the engine fires a set of internal triggers, updates the faction list, redraws the minimap, and notifies the AI. Doing it by hand can leave the campaign in an inconsistent state. Use the spawn script as the primary mechanism and treat direct emergence as a fallback for builds that support it.

Notes and pitfalls

  • The spawn script is engine‑only. Squirrel cannot replace it. It can only influence the conditions the script reads.
  • revolt vs end_of_turn. Choose carefully. revolt gives you context about which settlement revolted and from whom; end_of_turn gives you a chance to check any world condition you like, but has no revolt context.
  • Counters must exist before the spawn script reads them. Initialise any counter in a campaignMapLoaded handler.
  • Hidden resources are not saved. They are rebuilt from descr_regions on load. Re‑apply them on campaignMapLoaded if they need to persist.
  • Return true stops the script. The first return true in the spawn script exits it immediately. Everything after it — including the fallback return false — is skipped.
  • Do not edit the vanilla spawn scripts directly. Copy the script into your mod and reference it from your own descr_strat.txt.
  • Test emergence with a fresh campaign. Emergence state is baked into the campaign save at start.
  • The emergence block is read at load. Its unit list and strength are fixed when the campaign is loaded, so changes require a restart.
